要嫁就嫁（Yaojiajiujia）开发日志
================================================================

一、卡牌设计目标
----------------
- 夫白状态：可直接打出，获得格挡，正常进入弃牌堆
- 夫黑状态：由外部效果转化而来，回合结束自动转为夫白并打出，获得格挡
- 夫黑拥有 Retain 关键词，保留在手牌中直到回合结束

二、踩坑记录
----------------

坑1：OnPlay 中错误地调用了 Seal()
  症状：夫白打出后变为夫黑，多段打出导致卡牌卡死在夫黑
  修复：删除 OnPlay 中的 Seal()，夫白打出只获得格挡，不做状态转换

坑2：不明白卡牌设计意图，强行做了自作聪明的"循环设计"
  症状：把 CanonicalFufuState 改为 Black，加入了 AfterSideTurnStart 召回等复杂逻辑
  修复：恢复 CanonicalFufuState = White，回归用户原本简洁的设计

坑3：错误使用 BeforeSideTurnEnd 钩子
  症状：在卡牌上重写 ShouldReceiveCombatHooks = true 并用 BeforeSideTurnEnd
  原因：卡牌不参与 IterateHookListeners 迭代，钩子永远不会被分发到卡牌上
  修复：改回 HasTurnEndInHandEffect / OnTurnEndInHand 方案

坑4：一直不知道要同时更新 DLL 和 PCK
  症状：所有代码改动在游戏中无任何效果，控制台无日志输出
  原因：游戏从 E:\SteamLibrary\...\mods\ 加载 kyxiaofujiu.dll，
        但编译输出只到了本地 build\ 目录，从未复制过去
  修复：
    a) 手动复制 DLL 到游戏 mods 目录后确认有效
    b) 修改 .csproj 添加自动复制目标：
       <Copy SourceFiles="@(OutputDlls)"
             DestinationFolder="E:\SteamLibrary\steamapps\common\Slay the Spire 2\mods" />
    以后 dotnet build 会自动部署 DLL

坑5：夫白时也会有 OnTurnEndInHand 动画
  症状：HasTurnEndInHandEffect 始终返回 true，夫白卡牌虽无效果但会走一遍打出动画
  修复：改为 HasTurnEndInHandEffect => IsFufuBlack，夫白时不触发

三、最终代码
------------
public override bool HasTurnEndInHandEffect => IsFufuBlack;

protected override async Task OnPlay(...)
{
    await CreatureCmd.GainBlock(Owner.Creature, DynamicVars.Block, cardPlay);
}

protected override async Task OnTurnEndInHand(...)
{
    await base.OnTurnEndInHand(choiceContext);
    if (!IsFufuBlack) return;
    Unseal();
    await CreatureCmd.GainBlock(Owner.Creature, DynamicVars.Block, null);
}

四、关键经验
------------
1. DLL 和 PCK 都要部署，缺一不可
2. OnTurnEndInHand 是卡牌回合结束手牌效果的正确方案
3. 卡牌不参与 Combat Hook 迭代，BeforeSideTurnEnd 等钩子不会分发给卡牌
4. HasTurnEndInHandEffect 只在 DoTurnEnd 中被检查，用于手牌中的卡牌
5. OnTurnEndInHandWrapper 会自动：移入 Play → 调用 OnTurnEndInHand → 弃牌
6. 记录于 2026-07-19

蛇花小姐（SheHuaXiaoJie）伤害吸收机制 开发日志
================================================================

一、设计目标
----------------
- 征婚召唤物，HP = 征婚值 × 2，回合结束造成 3 次 × 征婚值 伤害
- 优先承受玩家未格挡伤害（类似奥斯提 Osty）
- 敌人大攻击到玩家 → 先扣玩家格挡 → 未格挡部分由蛇花小姐承受
  → 蛇花小姐不够扛的溢出伤害返回玩家
- 征婚扣血、其他自伤不触发阻挡
- 战斗结束晓夫九恢复蛇花小姐当前 HP

二、踩坑记录
----------------

坑1：用 AfterDamageReceived 回血式吸收 → 伤害先扣玩家再回血，一击毙命时来不及
  症状：敌人伤害 > 玩家当前 HP 时，玩家直接死，蛇花小姐活着也不挡
  原因：伤害先造成 HP 变化 → death check → AfterDamageReceived 才有机会回血
  尝试方案：
    a) ModifyDamageAdditive 减免伤害 → 影响敌人攻击意图数字显示
    b) BeforeDeath 拦截死亡并回血 → 来回血量计算复杂，不可靠
    c) SheHuaProtectionPower 独立 Power → ModifyDamageAdditive 不生效
  最终修复：照搬 Osty 的 ModifyUnblockedDamageTarget

坑2：ModifyDamageAdditive 影响攻击意图显示
  症状：敌人大攻击意图数字随征婚值减少，玩家无法判断真实伤害
  原因：ModifyDamageAdditive 修改了伤害数值本身，UI 直接显示修改后的值
  修复：改用 ModifyUnblockedDamageTarget 只改目标不改数值

坑3：Block（格挡）被绕过
  症状：ModifyDamageAdditive 在格挡前生效，玩家有格挡时蛇花小姐仍吃满伤害
  原因：ModifyDamageAdditive 在伤害计算最开始就拦截，早于格挡判定
  修复：ModifyUnblockedDamageTarget 只处理「未格挡」伤害，格挡先正常扣玩家

坑4：搞了一个复杂 Power 方案完全无用
  症状：SheHuaProtectionPower 里的 ModifyDamageAdditive 没被调用
  原因：MonsterModel 自身就是 ShouldReceiveCombatHooks=true，不需要额外 Power
  修复：删除 Power，直接把逻辑写在 MonsterModel 上

三、最终方案 — Osty 模式
------------------------
核心只有一个方法覆盖：

public override Creature ModifyUnblockedDamageTarget(
    Creature originalTarget, decimal amount, ValueProp props, Creature? dealer)
{
    // 玩家受到的未格挡伤害 → 目标重定向到蛇花小姐
    if (主人 == 被攻击目标 && 蛇花小姐存活)
        return Creature;  // 返回蛇花小姐自身
    return originalTarget;
}

游戏引擎原生伤害流程自动处理：
  1. Hook.ModifyDamage — 修改伤害数值（不影响）
  2. BeforeDamageReceived — 通知钩子
  3. Block 判定 — 玩家先扣格挡
  4. ModifyUnblockedDamageTarget — 改变「未格挡伤害」的目标 ← 我们只介入这里
  5. HP Loss 应用 — 打到蛇花小姐，溢出返回玩家

四、其他修正
----------------
- 攻击从 1 次大伤害 → 3 次小伤害（for 循环，每次 _marryCount）
- HP 公式修正：MinInitialHp=0，初始通过 Upgrade×n 设为 2×征婚值
- 征婚扣血加判断 dealer==null → 不被蛇花小姐拦截

五、关键经验
----------------
1. ModifyUnblockedDamageTarget 是 Osty 同款伤害重定向，不改 UI 不改 Block
2. MonsterModel 自身就可以收钩子（ShouldReceiveCombatHooks=true），不需要 Power
3. ModifyDamageAdditive 会改意图数字，只适合隐形加减伤，不适合做挡刀
4. AfterDamageReceived 回血的时机在 death check 之后，扛不住一击毙命
5. 直接读游戏源码（Osty.cs + CreatureCmd.cs + Hook.cs）比试一百种方案更高效
6. 记录于 2026-07-19

DynamicVars / CanonicalVars 缺失导致卡面数字不显示 — 修复日志
2026-07-22
================================================================

一、症状
--------
- 夫的女儿（Fudenver）卡面不显示格挡数值
- 突发恶疾（Tufaeji）卡面不显示能量和转化数量

二、根因
--------
两张卡都没有定义 CanonicalVars（DynamicVar 数组），导致本地化中的
{Block:diff()} / {Energy:diff()} / {Count:diff()} 无法解析。

正确模式（参考 Strikexiaofujiu / Defendxiaofujiu）：
  1. 定义 CanonicalVars 返回 DynamicVar[]（BlockVar / EnergyVar / IntVar 等）
  2. OnPlay 中通过 DynamicVars.Block.BaseValue 读取值
  3. OnUpgrade 中通过 DynamicVars.Block.UpgradeValueBy() 升级值
  4. 本地化使用 {VarName:diff()} 语法引用

三、修复内容
------------
Fudenver:
  - 添加 CanonicalVars: new BlockVar(4m, ValueProp.Move)
  - OnPlay: 硬编码 → (int)DynamicVars.Block.BaseValue
  - OnUpgrade: 空方法 → DynamicVars.Block.UpgradeValueBy(2m)
  - 本地化: {Block} → {Block:diff()}，删除硬编码 upgradeDescription

Tufaeji:
  - 添加 CanonicalVars: new EnergyVar(2) + new IntVar("Count", 2m)
  - OnPlay: 硬编码 → DynamicVars.Energy.BaseValue
  - OnUpgrade: 空方法 → DynamicVars.Energy.UpgradeValueBy(1m)

四、关键经验
------------
1. 卡牌必须定义 CanonicalVars，游戏用它驱动卡面数字和升级值
2. 本地化 {VarName:diff()} 必须在 CanonicalVars 中有对应 DynamicVar
3. upgradeDescription 不需要手动写，游戏根据 CanonicalVars + OnUpgrade 自动生成
4. 不要再硬编码 IsUpgraded ? a : b，全部走 DynamicVars

卡牌大全（Card Library）晓夫九筛选按钮 — 开发日志
2026-07-26
================================================================

一、需求
--------
- 游戏内卡牌大全界面没有晓夫九的专属筛选按钮
- 晓夫九卡牌分散在各筛选分类中，无法集中查看
- 需要添加一个类似铁甲战士/静默猎手那样的角色专属按钮

二、实现原理
------------
游戏卡牌大全（NCardLibrary）通过 _poolFilters 字典管理池筛选按钮：
  _poolFilters.Add(ironcladFilter, c => c.Pool is IroncladCardPool);
  _poolFilters.Add(silentFilter,   c => c.Pool is SilentCardPool);
  ...

按钮本身是 Godot 场景节点（%IroncladPool 等），由编辑器预设。
对于模组角色，无法编辑游戏场景，只能在运行时动态创建按钮。

三、实现方案
------------
通过 Harmony Postfix 补丁 NCardLibrary._Ready()：
  1. Traverse 反射获取私有字段 _poolFilters、_cardPoolFilters、_miscPoolFilter
  2. 克隆 _miscPoolFilter 节点（Duplicate()）作为晓夫九按钮
  3. 加载 xiaofujiu_icon.tscn 场景替换图标
  4. 设置 Loc = "晓夫九的卡组"（新增 characters.json key）
  5. 注册筛选函数：c => c.Pool is XiaofujiuCardPool
  6. 关联角色映射：_cardPoolFilters.Add(Xiaofujiu, filter)
  7. 连接 Toggled 信号实现 radio-button 互斥行为
  8. 连接 focus_entered 记录最后悬停控件

四、踩坑记录
------------

坑1：初次以为是"黑屏"崩溃
  症状：用户说点击卡牌大全黑屏
  排查：检查了全部 57 张卡牌注册、本地化、CanonicalVars 均无问题
  实际：并非崩溃，而是界面上根本没有晓夫九的筛选按钮，
        且默认选中铁甲战士筛选，看不到晓夫九的卡牌
  结论：差偏认知作为先古牌能正常显示，说明卡牌注册没问题，缺少的是 UI 按钮

坑2：克隆按钮保留了原 Misc 样式
  症状：按钮图标和描述显示为"状态诅咒事件和衍生牌"
  原因：Duplicate() 拷贝了原节点的所有属性
  修复：
    - 图标：加载 xiaofujiu_icon.tscn → 实例化 → 替换 Image 子节点
    - 描述：Loc 改为 characters/XIAOFUJIU.cardPoolTitle

坑3：UpdateCardPoolFilter 是 private 方法
  症状：无法直接获取 _Ready 中的局部变量 callable
  修复：用反射获取 MethodInfo，Delegate.CreateDelegate 创建委托，
        再通过 Callable.From 转为 Godot Callable 连接信号

五、涉及文件
------------
- kyxiaofujiuInitializer.cs                   （补丁5：NCardLibrary_Ready_Patch）
- kyxiaofujiu/localization/zhs/characters.json （新增 XIAOFUJIU.cardPoolTitle）

第四层建筑师对话卡死 — 修复日志
2026-07-26
================================================================

一、症状
--------
- 晓夫九进入第四层（Blight1 Era）见到建筑师后，无法进行任何操作，游戏直接结束
- 日志显示：TheArchitect_DialogueSet_Patch 注入成功，但随即 NGame.Quit

二、根因
--------
TheArchitect.DefineDialogues() 的 CharacterDialogues 字典只有 5 个本体角色
（Ironclad/Silent/Defect/Necrobinder/Regent），没有晓夫九的条目。
GetValidDialogues() 返回空列表 → LoadDialogue() 失败 → GenerateInitialOptions()
直接返回 ProceedOption → WinRun() → 游戏秒退。

三、第一次修复（失败）
--------------------
Postfix 补丁 DialogueSet getter，向 CharacterDialogues 注入 AncientDialogue。
症状：日志显示注入成功，但对话仍不生效，游戏秒退。

坑：PopulateLocKeys 时序问题
  PopulateLocKeys() 在 getter 中 DefineDialogues() 返回后立即执行，
  遍历 CharacterDialogues 调用 PopulateLines() 初始化 LineText/Speaker。
  我们的 Postfix 在 getter 返回后才注入，此时 PopulateLocKeys 早已执行完毕，
  新对话的 Lines 从未被 PopulateLines 初始化 → LineText 为空 → Dialogue 无效。

四、第二次修复（成功）
---------------------
在 Postfix 中：
  1. 手动调用 dialogue.PopulateLines("THE_ARCHITECT", charKey, 0)
     → 初始化 3 句对话的 LineText 和 Speaker
  2. 手动设置前 2 行的 .next 按钮文本
     → line.NextButtonText = LocString("ancients", "{key}.next")
  3. ancients.json 新增 .next 本地化 key（0-0.next, 0-1.next）

对话流程：建筑师→晓夫九→建筑师，EndAttackers=Architect 让建筑师击杀晓夫九。

五、涉及文件
------------
- kyxiaofujiuInitializer.cs                          （补丁6：TheArchitect_DialogueSet_Patch）
- kyxiaofujiu/localization/zhs/ancients.json          （新建，建筑师对话本地化）

六、关键经验
------------

夫态图标重叠（转化后旧图标不清除）— 修复日志
================================================================

一、症状
--------
- 初始夫白正常（卡面一个图标），转化为夫黄后新旧图标重叠
- 夫白翅膀大，下层仍可见，遮不干净

二、根因
--------
- kyxiaofujiuInitializer.cs 的 NCard_UpdateVisuals_Patch：
  每次 UpdateVisuals（卡牌视觉刷新，很频繁）都调用 FufuOverlayHelper.Add
- FufuOverlayHelper.Clear 用 child.QueueFree()，是延迟到下一帧才删除
- 转化时同一帧内 RefreshOverlay + 多次 UpdateVisuals 都会触发 Add，
  旧图标节点被 QueueFree 后当前帧仍在容器中，新图标又加进来 → 重叠

三、修复
--------
- Clear 改为 container.RemoveChild(child) + child.QueueFree()，立即移除旧图标
- 添加新图标前旧图标即刻清除，卡面上始终只有一个图标
- 图标位置/大小保持原本设计（96×96，-100,-300）

四、关键经验
------------
1. QueueFree 是延迟删除（帧末才删），同帧内多次 AddChild 会残留旧节点
2. 需要立即清空容器子节点时，用 RemoveChild 先移除再 QueueFree
3. 排查"重叠"类问题先找所有 Add 入口（Harmony patch 也会反复 Add）

  流程：
  1. ffmpeg 抠白幕提取帧：colorkey=0xFFFFFF:0.08:0.05 → 121帧

  4. 生成 SpriteFrames .tres（AtlasTexture 子区域引用）+ 预览场景 idle_preview.tscn

     CustomCreatureVisuals._Ready 调 Play("idle")
  ⚠️ 坑1：SpriteFrames .tres 中 SpriteFrames 必须作为顶层 [resource] 段（animations 直接属于它），
        不能写成 sub_resource，否则 Godot 解析失败报"缺少依赖项"
  ⚠️ 坑2：tres 引用纹理的 uid 必须与 .import 里 Godot 实际生成的 uid 一致！
        Godot 导入 png 时会重新生成 uid，手写 .import 的 uid 会被覆盖 → 对不上就报缺少依赖项。
        修法：读 .import 里的真实 uid 填进 tres 的 ext_resource
  ⚠️ 坑3（重要）：白幕视频抠图，角色身上有近20%浅色像素（脸/腿/胳膊近白），colorkey/PIL距离法
        都会把浅色区域误抠成透明→黑边（脸实心仅77%）。改用 rembg（U2Net AI前景分割）
        脸实心达99.7%，正确识别角色轮廓而非按颜色。命令：pip install rembg onnxruntime
  ⚠️ 坑4：AnimatedSprite2D 只设 animation 属性不会自动播放，必须在代码 _Ready 里 Play()。
        预览脚本 IdlePreview.cs（项目根）专门打印动画列表/加载错误
  ⚠️ 坑5：tres 手写时不要用 PowerShell 字符串插值生成 region（$x/$y 变量会被错误解析成
        System.Xml.XmlDocument 等，写坏文件），用 Python 生成最稳
  产物：images/animations/idle_sheet.png(+import)、animations/idle_sheet.tres、
        scenes/animations/idle_preview.tscn、IdlePreview.cs、xiaofujiu.tscn 接入
